Comando de treino pesado com horas configuráveis
Opção 1 — Forma mais limpa (PowerShell), passando horas direto pro orchestrator
$hours = 1
.venv\Scripts\python.exe -m ml_engine.ray_cluster.orchestrator `
  --arena-only `
  --budget-hours $hours `
  --num-workers 4 `
  --num-trials 4 `
  --batch-size 2000 `
  --checkpoint-freq 10 `
  --perturbation-interval 20
Só troca o valor de $hours (aceita decimal — 0.5 = 30 minutos, 12 = 12 horas, 24 = 1 dia, etc.).

Opção 2 — Via npm script com a env var, passando horas como flag extra
O npm run train:ray:arena já garante o TRAINING_POOL_ARENA_ONLY=1 e o --arena-only. Você só precisa passar --budget-hours extra com --:

npm run train:ray:arena -- --budget-hours 8 --num-workers 4 --num-trials 4 --batch-size 2000
O -- separador faz o npm repassar tudo pro Python (o jeito que cross-env propaga args).

Referência rápida das flags relevantes
Flag	Default	O que faz
--budget-hours
24.0
Para após N horas (aceita decimal: 0.5 = 30min)
--num-workers
4
Rollout workers por trial PBT (mais = mais Forge JVMs em paralelo)
--num-trials
4
Tamanho da população PBT (mais = mais hyperparams explorados)
--batch-size
500 (CLI)
Train batch size IMPALA (auto-aligned pra ser múltiplo de rollout-fragment-length)
--checkpoint-freq
10
Salva checkpoint a cada N iterações
--perturbation-interval
20
PBT muta hparams a cada N iterações
--max-cards
64
Cap de nodes na obs (lower = menos RAM)
--arena-only
(env var)
Força Arena pool (ignora env var)
--deck-seed
None
Seed pra archetype matchup (deterministico)

Se quiser forçar fração de GPU por trial (default = 0.25 quando CUDA disponível):

.venv\Scripts\python.exe -m ml_engine.ray_cluster.orchestrator --arena-only --budget-hours 8 --num-workers 2 --num-trials 2

Para CPU forçada:
